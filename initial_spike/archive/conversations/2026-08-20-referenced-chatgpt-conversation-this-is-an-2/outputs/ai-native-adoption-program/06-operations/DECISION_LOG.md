## `DEC-OPS-0004`: Adopt first-principles quality bar and standards alignment

- Date: 2026-08-20
- Status: proposed
- Decision: use first-principles review, standards alignment, locale/community validity, and value-generation logic as quality gates for the v0.2 program.

## `DEC-OPS-0005`: Govern documents by lifecycle class

- Date: 2026-08-20
- Status: proposed
- Decision: classify documents as constitutional, standards, architecture, living operating records, study definitions, study outputs, human-authored reports, or generated views before editing or approving them.
- Rationale: the repository now has enough documentation that unmanaged edits would weaken trust, traceability, and review sustainability.
- Consequences: locked, released, append-only, and generated artifacts should not be casually edited; updates should use amendments, versions, superseding documents, or source regeneration.
- Linked IDs: `DOC-OPS-0007`

## `DEC-OPS-0003`: Add v0.2 architecture domains additively

- Date: 2026-08-20
- Status: proposed
- Decision: add Intelligence Graph, Registries, Trust, and Product as new top-level domains without deleting, renaming, or renumbering existing v0.1 folders.
- Rationale: the program needs explicit ownership for knowledge architecture, structured source-of-truth records, evidence trust, and commercial product packaging.
- Consequences: the v0.1 Wild-Lab-Sandbox loop remains intact while new artifacts can mature around it.
- Linked IDs: `DOC-FOUND-0006`, `DOC-IG-0001`, `DOC-REG-0001`, `DOC-TRUST-0001`, `DOC-PROD-0001`

## `DEC-OPS-0001`: Use one program with three tracks

- Date: 2026-08-20
- Status: accepted
- Decision: organize Wild, Lab, and Sandbox as one program with a shared evidence substrate.
- Rationale: the tracks answer complementary questions: what happens, why it happens, and what can be improved externally.
- Consequences: documents, registries, experiments, and findings should use shared IDs and cross-track links.

## `DEC-OPS-0002`: Start with a narrow closed loop

- Date: 2026-08-20
- Status: proposed
- Decision: the first milestone should prove one complete loop before broad benchmark expansion.
- Rationale: early breadth can hide whether the operating model works.
- Consequences: initial implementation should favor one journey, a few languages, and one treatment.
